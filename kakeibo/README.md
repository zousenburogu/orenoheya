# 残高予測家計簿

給料日から次の給料日までの口座残高の推移を予測する、個人用の家計簿 Web アプリです。
ビルド不要の静的ファイルだけで動き、データはブラウザの localStorage に保存されます（外部送信なし）。

## 使い方

- `kakeibo/index.html` をブラウザで開く（GitHub Pages などに置けばスマホからも使えます）
- 初回は「サンプルデータで試す」で動作を確認できます
- 「メニュー › 設定・データ」から JSON で書き出し・読み込みができます（機種変更・バックアップ用）

## 機能と設計書との対応

| 設計書 | 実装 |
|---|---|
| 3.1 収入管理 | 給与明細（支給・控除・差引支給額の自動計算、残業の時給換算、残業時間から次回の手取り見込み → 給与予定として登録）、ボーナス・臨時収入は収入カテゴリで登録 |
| 3.2 支出管理 | 定期ルール（毎月・隔月など、月2回などの複数日、末日、休日の前後営業日調整）、平日／休日単価の日割り生活費、月の雑費枠（日割り）、単発の支出、定期の口座間振替 |
| 3.3 口座管理 | 複数口座、合計に含めない口座（PayPay残高など）、振替のステータス（予定→申請中→着金待ち→着金済み）と残高への自動反映、着金予定日超過のアラート |
| 3.4 予測 | 日別残高グラフ（タップで内訳）、最低残高の日の自動検出、期間指定、What-if（保存しない仮の支出）、着金待ちの「着金する／しない」2パターン比較、日別の表 |
| 3.5 目標 | 誕生日・何歳まで・いつから貯め始めるかで期日を自動計算（日付での直接指定も可）、必要な年間・月間貯金額の逆算、12か月予測または手入力のペースとの比較、臨時収入を含める／除外 |
| 3.6 カテゴリ分析 | 期間内のカテゴリ別横棒グラフ、タップで内訳、予定分を含める切り替え |
| 3.7 外部比較 | カテゴリごとに比較基準（月額）を手入力し、バーに基準線を表示 |
| 3.8 アラート | 残高の閾値割れ・マイナス予測、未着金、日付を過ぎた未確定の予定、臨時収入の年間合計による確定申告の目安（任意でブラウザ通知） |

## 残高の考え方

- 口座の残高は「今の実際の残高」。銀行アプリを見て「残高更新」で合わせられます
- 予測は今日の残高から、今日以降の定期ルール・予定・振替・日割り生活費を積み上げて計算します
- 予定は実際に払ったら「支払済」（収入は「入金済」）。未来の日付の予定で押すと確認のうえ今日の日付で計上します
- 「支払済」「済」は直後のトーストの「元に戻す」、またはホーム／入力画面の「予定に戻す」で取り消せます（残高も元に戻ります）
- 定期ルールの回は「済」で残高に反映され、予測から外れます。後払いなど毎回金額が違うものは「変更」でその回だけ上書きできます
- 生活費・雑費は見込み（日割り）だが、実績を記録するとその分は見込みから差し引く（今日の生活費は「1日の単価 − 今日の実績」、今月の雑費は「月の枠 − 今月の実績」を残りの日数で日割り）
- 休日判定は土日・祝日（振替休日・国民の休日を含む）＋会社の休みとして指定した日です

## 金額の入力

金額欄はすべて計算式が使えます（例: `=1+2`、`12,000-3500`、`2万+3000`、`(1200+800)*3`）。入力中は下に結果が表示され、欄から離れると結果の数字に置き換わります。スマホでは欄を選ぶと ＋ − × ÷ ( ) ＝ のキーが出ます。

## 画像から取り込む

「入力 › 画像から取り込む」（またはメニュー）で、レシート・残高・請求・給与明細の画像を Claude に読み取らせて取り込めます（API キー不要・追加料金なし）。

1. 「依頼文をコピー」→ Claude のアプリで画像を添付し、依頼文を貼り付けて送信
2. Claude が返した CSV をアプリに貼り付けて「読み込む」
3. 種類ごとに振り分けられた内容を確認・修正して「登録する」

| 行の種類 | 取り込み先 |
|---|---|
| `支出,日付,金額,内容,口座,カテゴリ` | 支出（未来日付は予定） |
| `収入,日付,金額,内容,口座,カテゴリ` | 収入 |
| `残高,日付,金額,,口座,` | 口座の残高更新（差額は残高調整として記録。ほかの行より後に反映） |
| `請求,引き落とし日,金額,サービス名,口座,` | 名前の近い定期ルールのその回の金額を上書き（なければ単発の予定） |
| `給与明細,支給日,支給額合計,控除額合計,残業時間,時間外手当` | 給与明細＋手取りを給与口座に記録（同じ頃の給与記録があれば二重にしない） |

口座名・カテゴリ名・サービス名は表記ゆれ（「後払い／あと払い」など）を吸収して照合します。同じ日・同じ金額の記録がすでにある行は、最初から取り込み対象外になります。

## 給料期間の収支

「メニュー › 給料期間の収支」。期間は「給料日〜次の給料日の前日」。

- **集計**：期間ごとに平日・休日の日数、収入、生活費（平日日数×平日単価＋休日日数×休日単価）、雑費（1期間につき月の雑費額）、固定費、返済、費用合計、貯金見込み、累計。区分ごとの積み上げ棒グラフと累計
- **カレンダー**：予定のある日に印（＋収入・−支払い・別＝別口座）。給料日の左に区切り線。下にその月の予定一覧（給料などは「変更」でその月だけ金額を上書き）
- **予定**：名前・金額・区分（収入／固定費／返済）・日付（単発／毎月X日／毎月の給料日）・開始月・終了月・支払い元を登録。「合計に含めない口座」を支払い元にすると集計から除外（カレンダーには表示）
- **予算枠**：期間と使える額から、1日あたり使える額・生活費ルールの見込み（雑費を含めるか切り替え、給料期間の途中からは日割り）・過不足
- **リボ**：残高・月々の返済額・年利・一括返済する月から返済スケジュールと利息の合計（利息＝残高×年利×その月の日数÷365）
- 区分はカテゴリごとに設定（「メニュー › カテゴリ」）。生活費・雑費のカテゴリの取引はルール計算と二重になるので集計に含めない
- 「指示書の初期データを追加」で 2026年10月〜2027年1月の予定・設定を今のデータに追加できる（同じ予定はとばす）

## 稼ぐ目安カレンダー

「メニュー › 稼ぐ目安カレンダー」（目標の画面・ホームの目標カードからも）で、平日1日あたりいくら稼げばいいかをカレンダーで表示します。「年収目標」と「貯金目標」を切り替えられます。

**年収目標**（初期値：年収400万円・基本給月18万円。ボーナスは年間合計を入力）

- 今年の月：平日1日あたり（額面）＝（年収の目標 − もらった給料 − これからの基本給 − まだもらっていないボーナス）÷ 今日から年末までの平日数。給料が入るたびに更新される
  - もらった給料は月ごとに、給与明細の支給額 → なければ給与の入金（手取り）を控除率で額面に戻した額 → どちらもなければ基本給で仮定（画面の「月ごとの支給額」で確認できる）
- 来年以降の月：平日1日あたり（額面）＝（（年収の目標 − ボーナス）÷ 12 − 基本給）÷ その月の平日数
- 残業時間 ＝ 額面 ÷ 残業1時間あたりの手当（給与明細から。なければ基本給 ÷ 約163時間 × 1.25 で推定）
- 給与明細があれば、今年の支給額の合計と目標までの残りも表示

**貯金目標**

- 平日1日あたり ＝（必要な月の貯金 − 今のペース）÷ その月の平日数（土日・祝日・会社の休みを除く）
- 給与明細があれば、直近の控除率で額面に、残業1時間あたりの手当で残業時間にも換算
- 今のペースで届く月は ✓ を表示。過去の日と目標期間の外の日は数字を出さない

## 記録のリマインダー

- 「メニュー › 設定・データ › 記録のリマインダー」で時刻（初期値 21:00）を設定
- アプリを閉じているときの通知は、iPhone のリマインダーアプリ（Siri や Claude アプリからでも可）で「毎日・その時刻」の繰り返しを登録して使う
- アプリを開いたとき（または開いたまま時刻になったとき）に今日の記録がなければ、ホームに「まだ記録がありません」と表示。「今日は使っていない」で消せる

## ファイル構成

```
kakeibo/
  index.html
  css/style.css
  js/dates.js    日付・祝日・営業日
  js/engine.js   計算ロジック（DOM 非依存）
  js/chart.js    SVG グラフ
  js/importer.js 画像読み取り結果（CSV）の取り込み
  js/periods.js  給料期間の集計・予算枠・リボ・初期データ
  js/app.js      画面
  test/engine.test.js
```

## 更新時の注意（バージョン番号）

Safari などが古いファイルを使い続けないよう、`index.html` の `data-version` と各ファイルの `?v=` にバージョン番号を付けています。
ファイルを変更したら、この番号（`index.html` 内のすべての `?v=` と `data-version`）をまとめて新しい値に変えてください。開いている画面に「新しいバージョンがあります」と表示されます。
