# 残高予測家計簿

給料日から次の給料日までの口座残高の推移を予測する、個人用の家計簿 Web アプリです。
ビルド不要の静的ファイルだけで動き、データはブラウザの localStorage に保存されます（外部送信なし）。

## 使い方

- `kakeibo/index.html` をブラウザで開く（GitHub Pages などに置けばスマホからも使えます）
- 初回は「サンプルデータで試す」で動作を確認できます
- 「メニュー › 設定・データ」から JSON で書き出し・読み込みができます（機種変更・バックアップ用）

## 機能と設計書との対応

| 設計書 | 実装 |
|---|---|
| 3.1 収入管理 | ボーナス・臨時収入は収入カテゴリで登録（給料は定期ルールで登録） |
| 3.2 支出管理 | 定期ルール（毎月・隔月など、月2回などの複数日、末日、毎月の第N曜日（例：第1金曜）、毎週・N週ごとの曜日指定、休日の前後営業日調整）、平日／休日単価の日割り生活費、曜日と金額で決めるまとめ買い、月の雑費枠（日割り）、単発の支出、定期の口座間振替 |
| 3.3 口座管理 | 複数口座、合計に含めない口座（PayPay残高など）、振替のステータス（予定→申請中→着金待ち→着金済み）と残高への自動反映、着金予定日・メモの編集（「編集」。残高は動かない）、着金予定日超過のアラート |
| 3.4 予測 | 日別残高グラフ（タップで内訳）、最低残高の日の自動検出、期間指定、What-if（保存しない仮の支出）、着金待ちの「着金する／しない」2パターン比較、日別の表 |
| 3.6 カテゴリ分析 | 期間内のカテゴリ別横棒グラフ、タップで内訳、予定分を含める切り替え |
| 3.7 外部比較 | カテゴリごとに比較基準（月額）を手入力し、バーに基準線を表示 |
| 3.8 アラート | 残高の閾値割れ・マイナス予測（着金待ちは着金予定日に入る前提）、着金予定日の当日に入る額の「お知らせ」、未着金、日付を過ぎた未確定の予定（任意でブラウザ通知） |

## 残高の考え方

- 口座の残高は「今の実際の残高」。銀行アプリを見て「残高更新」で合わせられます
- 予測は今日の残高から、今日以降の定期ルール・予定・振替・日割り生活費を積み上げて計算します
- 予定は実際に払ったら「支払済」（収入は「入金済」）。未来の日付の予定で押すと確認のうえ今日の日付で計上します
- 「支払済」「済」は直後のトーストの「元に戻す」、またはホーム／入力画面の「予定に戻す」で取り消せます（残高も元に戻ります）
- 定期ルールの回は「済」で残高に反映され、予測から外れます。後払いなど毎回金額が違うものは「変更」でその回だけ上書きできます
- 生活費・雑費は見込み（日割り）だが、実績を記録するとその分は見込みから差し引く（今日の生活費は「1日の単価 − 今日の実績」、今月の雑費は「月の枠 − 今月の実績」を残りの日数で日割り）
- 生活費は「まとめ買い」と「日割り」に分けられる（「生活費の設定 › まとめ買い」）。まとめ買いは「毎週土曜 4,000円」のような生活費カテゴリの定期ルールで、予測ではその日にまとめて減る。買ったら「これからの予定」で「済」（金額が違えば「変更」）にする。「済」で記録した分は日割りの見込みからは引かない（二重に差し引かない）。毎日少しずつ使う分だけ「1日あたり」に入れる
- 定期ルールは「月ごと（日にち）」「月ごと（第N曜日。第1〜第4・最終）」「週ごと（毎週・2〜4週ごと、曜日）」を選べる。支出・収入・口座間の振替のどれでも使える（例：毎週月曜に貯金口座へ振替）。N週ごとは開始日以降で最初のその曜日が起点
- 生活費を払う口座は複数選べる（「生活費の設定」）。上から順に、1日分を払える最初の口座から払う（残り僅かで払えない口座は使い切らず次の口座へ自動で移る）見込みで予測。全部なくなる見込みならホームに警告
- 「残高が足りないとき立て替える口座」（生活費の設定）を選ぶと、支出で残高が足りなくなる見込みのとき、不足分を上から順にその口座から払う見込みで予測（口座間の振替は対象外）
- 残高のない口座は、生活費の口座に選ぶとエラー表示。支出・振替の入力で残高のない口座を選ぶとエラーが出て、残高より大きい額は登録できない（予定や「残高はもう更新済み」は除く）
- 休日判定は土日・祝日（振替休日・国民の休日を含む）＋会社の休みとして指定した日です

## FX口座への入金・出金（振替）

FX口座とのお金の移動は「振替」で記録します。

- FX口座への入金・FX口座からの出金は「振替」で記録する（銀行 → FX口座、FX口座 → 銀行）。出金は着金までは「着金待ち」にしておき、着金したら「着金した」を押す。振替なので支出・収入の集計には入らない
- 「着金した」では実際に入った金額を直せる。予定と違えば、その差を入金先に「着金額の差」として記録する（FX口座からの出金なら、差はFXの損益に入る）
- ホームの残高見込みとアラートは、着金待ちが着金予定日に入る前提で計算する（入らなかった場合の額はホームに小さく表示）
- 着金予定日がずれたら、「口座 › 振替・出金の状況」の「編集」で日付を直す（メモも直せる。残高は動かない）

## 金額の入力

金額欄はすべて計算式が使えます（例: `=1+2`、`12,000-3500`、`2万+3000`、`(1200+800)*3`）。入力中は下に結果が表示され、欄から離れると結果の数字に置き換わります。スマホでは欄を選ぶと ＋ − × ÷ ( ) ＝ のキーが出ます。

## 修正ファイルで予定・収入をまとめて直す

「メニュー › 設定・データ › 修正ファイルを読み込む」で、予定・収入の追加・変更・削除をJSONでまとめて反映できます（全データを置き換える「JSONを読み込む」とは別の機能です）。

1. 修正ファイルを選ぶか、JSONを貼り付けて「差分を確認」。追加・変更・削除の一覧と、適用しない行（対象が見つからない・複数一致など）、注意点が出ます。まだデータは変わりません
2. 内容を確認して「適用する」。適用前のデータは自動でバックアップされ、直後のトーストの「元に戻す」、または設定・データの「修正ファイル適用前に戻す」で戻せます

```json
{ "edits": [
  { "action": "add", "type": "income", "date": "2026-10-09", "amount": 1000, "label": "名前", "account": "口座名", "category": "カテゴリ名" },
  { "action": "add", "type": "expense", "date": "2026-10-09", "amount": 300, "label": "名前", "account": "口座名", "category": "カテゴリ名", "reflected": true },
  { "action": "change", "target": "名前", "from": { "date": "2026-10-05", "amount": 500 }, "to": { "date": "2026-10-09", "amount": 600, "label": "新しい名前", "category": "カテゴリ名" } },
  { "action": "change", "target": "FX出金", "from": { "date": "2026-10-27", "amount": 50000 }, "to": { "date": "2026-10-28" } },
  { "action": "delete", "target": "名前", "date": "2026-10-05", "amount": 500 },
  { "action": "add-account", "name": "口座名", "includeInTotal": false, "balance": 0, "note": "メモ" },
  { "action": "transfer", "date": "2026-10-27", "amount": 50000, "from": "FX口座", "to": "銀行", "label": "FX出金", "status": "着金待ち" },
  { "action": "add-recurrence", "label": "電気代", "type": "expense", "amount": 10000, "account": "銀行", "category": "固定費", "nth": 1, "weekday": "金", "adjust": "next", "start": "2026-11-01" },
  { "action": "fx", "date": "2026-10-25", "pl": 12000, "rebate": 3000 }
] }
```

- 上の行から順に適用します（直前の追加を次の行で変更することもできます）
- **add**：`type` は `income`（収入）か `expense`（支出）。未来の日付は予定、今日以前は実績（口座の残高も動く）。同じ日・同じ金額（口座が決まっていれば同じ口座）の記録がすでにあればスキップ。`account` を省くと収入は給与口座・支出は生活費の口座。口座名やカテゴリ名は表記ゆれを吸収して照合（見つからない口座はエラー、見つからないカテゴリは近いものに寄せて注意を表示）。`"reflected": true` を付けると「残高に反映済み」の実績として記録し、口座の残高は動かしません（残高調整に含まれていた支払いを後から記録するとき用。未来の日付では使わず予定になります）
- **change**：`target`（名前）と `from` の日付・金額で、単発の予定・実績、または定期ルールの1回分を特定し、`to` の日付・金額・名前（`label`）・カテゴリ（`category`）に変更（`to` はどれか1つだけでも可）。定期ルールの1回分はその回の日付・金額だけ上書きし、ルール自体は変えません（名前・カテゴリは変えられません）。「残高調整」に名前かカテゴリを付けると、ふつうの記録として集計に入ります。残高に反映済みの記録（残高調整など）は、金額を変えても口座の残高は動きません。見つからない・複数一致するときは適用しません。振替も同じ書き方で、`target`（メモか口座名）と `from` の日付・金額で特定し、日付（着金予定日）とメモ（`label`）だけ変えられます（口座の残高は動きません。金額・カテゴリの変更は適用しません）
- **delete**：`target`・`date`・`amount` で特定して削除。定期ルールの1回分は「その回を外す」扱い。見つからなければ適用しません
- **add-account**：口座を作ります。`name`（口座名・必須）、`includeInTotal`（合計に含めるか。`true`/`false`、省略時は `true`）、`balance`（今の残高。入れると記入済みになり、省略すると残高は未記入のまま）、`note`（メモ）。口座は他の行より先に作るので、同じファイルの予定でその口座名を使えます。同じ名前（表記ゆれを吸収して照合）の口座がすでにあれば「既にあるためスキップ」。口座名が空、`balance` が数字でないときは適用しません
- **transfer**：口座間の振替を作ります。`from`・`to`（口座名）、`date`、`amount`、`label`、`status`（予定・申請中・着金待ち・着金済み。省略時は今日以前なら着金済み、未来なら予定）。`"reflected"` に `"from"`・`"to"`・`"both"` を付けると、その側の口座の残高には反映済みとして残高を動かしません（残高調整で合わせてあった入出金を振替に直すとき用）。同じ日・同じ金額・同じ口座の振替があればスキップ
- **add-recurrence**：定期ルールを作ります。`label`、`type`（income・expense・transfer）、`amount`、`account`（振替は出金元）、`to`（振替の入金先）、`category`、`start`（省略時は今日）・`end`、`adjust`（none・next・prev。休日の扱い）、`everyMonths`（何か月ごと）。日付は `day`／`days`（日にち。末日は「末」）、`"payday": true`（毎月の給料日）、`nth`（1〜4、最終は -1）＋`weekday`（「金」や 0〜6）、`weeks`（1〜4）＋`weekday` のどれかで指定。同じ名前・金額・口座のルールがあればスキップ。同じ名前の単発の予定が残っていると二重になるので注意を表示します（先に delete で消してください）
- **fx**：FXの日ごとの損益・リベートを、FX口座の取引として記録します（確認する画面は今はなく、残高と取引に反映されます）。`date`（今日まで）、`pl`（損益。マイナス可）、`rebate`（リベート）、`account`（省略時はFX口座）、`"reflected": true`（FX口座の残高に反映済み）。同じ日の記録があれば、同じ内容ならスキップ、違えば適用しません
- 金額の符号は見ません（絶対値で照合し、change では元の符号を保ちます）。名前は完全一致のほか、一方がもう一方を含めば一致とみなします
- 修正ファイルには個人の金額が入るので、公開リポジトリにはコミットしないでください

## バックアップの促し

データはブラウザ内だけに保存されるため、最後に「JSONを書き出す」（またはホームの「今すぐ書き出す」）から7日たつと、ホームに案内が出ます。まだ書き出したことがなければ、使い始めた日から数えます。

## 記録のリマインダー

- 「メニュー › 設定・データ › 記録のリマインダー」で時刻（初期値 21:00）を設定
- アプリを閉じているときの通知は、iPhone のリマインダーアプリ（Siri や Claude アプリからでも可）で「毎日・その時刻」の繰り返しを登録して使う
- アプリを開いたとき（または開いたまま時刻になったとき）に今日の記録がなければ、ホームに「まだ記録がありません」と表示。「今日は使っていない」で消せる

## 更新時の注意（バージョン番号）

Safari などが古いファイルを使い続けないよう、`index.html` の `data-version` と各ファイルの `?v=` にバージョン番号を付けています。
ファイルを変更したら、この番号（`index.html` 内のすべての `?v=` と `data-version`）をまとめて新しい値に変えてください。開いている画面に「新しいバージョンがあります」と表示されます。
